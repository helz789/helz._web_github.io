水-能源-糧食面向下高雄市生態系服務供需與熱點分析

發布日期：2026年02月01日

🌍 氣候變遷下的城市挑戰

近年來，全球氣候變遷與都市化進程加速，讓生態系統的功能與結構面臨前所未有的壓力。這些改變不僅影響自然環境，也直接牽動人類賴以生存的生態系服務(Ecosystem Services, ES)。其中，水、糧食與能源(WEF)是維持城市永續發展的三大核心要素，彼此之間高度鏈結、相互影響。如何在這樣的複雜網絡中理解供需平衡，成為資源管理與政策制定的重要課題。

🔧 方法與分析

本研究以高雄市為案例，運用 InVEST模型套件，挑選六項代表性生態系服務: 年水量產出、泥沙輸送、碳儲存與固碳、農作物產量、洪水風險調適，以及都市降溫。透過建立供需指標(ESDR)，並結合空間統計方法(Getis-Ord Gi* 熱點分析與 Local Moran’s I 局部空間自相關)，辨識出供需失衡與永續性風險區域。這樣的分析不僅揭示了城市不同區域的資源壓力，也提供了更精細的空間規劃依據。

使用 Python 自動化處理 GIS 資料需要注意哪些事？

發布日期：2025年12月19日

在處理大量地理空間資料時，手動操作既耗時又容易出錯。透過 Python腳本進行自動化， 可以把「裁切、重投影、重採樣、統計分析」這些重複步驟交給程式，大幅提升效率， 也讓整個流程更容易被重現與檢查。

為什麼要用 Python自動化處理 GIS資料？

在做 GIS相關研究時，常常會遇到「同樣的步驟要對很多圖層，或是多年份重複做」的情況。 雖然 ArcGIS Pro中已經有 Model Builder這種 no code自動化的工具，但若在今天資料量非常之大的情形，若完全依賴 GIS內部手動操作，不但仍舊需要消耗一定時間，也難保每次設定完全一致。

因此若透過 Python把流程寫成腳本，可以一口氣處理整個資料夾的檔案，也可以讓不同區域、年度重複使用同一套流程，對於研究的重現性非常重要。

1. 資料格式與座標系統(CRS)

自動化前第一件事，是確認每一個圖層的座標系統(Coordinate Reference System, CRS)： 向量資料(Shapefile/GeoJSON)常見是 EPSG:4326或各種平面座標系統， 網格資料(GeoTIFF/NetCDF)又可能是不同的投影。

在 Python裡做重投影時，最好先決定「分析用的統一投影」，例如適合距離或面積計算的等積投影， 然後再用 rasterio、gdal 等工具把所有資料轉成同一 CRS。 另外也要注意單位，有些是「度」，有些是「公尺」，如果忽略了這點，在計算坡度、距離或流量時會出現錯誤的結果。

2. NoData、解析度與像元對齊

很多 DEM或衛星影像都有 NoData值，例如 -9999、0 或 255。 在做加減乘除或統計之前，應該先把 NoData過濾或統一處理，避免錯誤值被算進去。

不同資料來源的解析度都不一樣(ex: 10m、90m、100m、1km等)。因此疊加分析前， 最好先重採樣為同一解析度，並以某一張 raster當作 template做像元對齊， 避免出現「解析度一樣，但網格錯一格」的情況。

3. 檔案結構與命名規則

自動化腳本通常會掃描整個資料夾讀檔，因此清楚的資料夾結構非常重要。 建議把資料區分為 raw/、preprocessed/、output/ 等層級， 檔名也盡量包含「區域＋年份＋指標」，例如： taiwan_lulc_2020.tif、taiwan_rainfall_2010_2020.nc。命名規則一旦固定下來，之後的腳本就可以用前綴/後綴自動抓檔，維護起來也比較不容易崩潰。

4. 記憶體與效能管理

面對大範圍的網格資料，不建議一次整張讀進記憶體。 可以利用 rasterio 的 window/block 機制分塊處理， 或視情況使用暫存檔，減少記憶體壓力與磁碟 I/O。在處理多個檔案時，也可以在迴圈中印出目前進度(第幾個檔案)，有助於 debug與掌握大致計算時間。

5. 可重現性：環境與版本控制

如果希望之後自己或別人能重現同樣的分析結果， 建議固定好 Python與套件版本，並把設定寫在 requirements.txt 或 environment.yml 中， 例如指定 python、rasterio、gdal 的版本，避免安裝環境時產生諸多環境不相容的問題。此外，用 Git管理程式碼，可以清楚知道「哪一個 commit做了哪一次分析」，未來需要修改流程或修 bug，也比較容易回溯。

6. 流程設計：模組化與參數化

建議把整個流程拆成多個小函式，例如： clip_to_boundary()、reproject_raster()、 compute_zonal_stats() 等。這樣未來換研究區域，或加入新的指標時，只要重新組合函式即可。除此之外，重要的設定，例如研究區名稱、目標 CRS、解析度等，也可以集中在腳本開頭的設定區，之後會較好更改。

7. 和桌面 GIS工具搭配

即使使用 Python自動化，GIS軟體仍然是非常重要的工具。 前處理時可以用桌面 GIS檢查資料品質、畫 AOI、確認顏色與範圍； 自動化腳本則負責「大量重複」和「需要多次重跑」的部分。計算完成後，把輸出的 GeoTIFF或 Shapefile丟回 GIS軟體，檢查高值區是否真的落在預期位置、有沒有異常線條或空洞，可以避免很多肉眼難以察覺的錯誤。

小結

使用 Python自動化處理 GIS資料，關鍵不是寫出多複雜的程式， 而是養成幾個好習慣： 先整理好資料(CRS、解析度、NoData)、設計清楚的流程與命名規則，並且讓環境與程式版本可以被記錄與重現。

以上，是我目前在這塊領域的小心得，只要有這些基礎，在做相關研究時， 都能夠在同一套自動化流程上不斷疊加新的想法，而不用每次從零開始。
